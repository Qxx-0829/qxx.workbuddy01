# Skill

## 学习目标

- 能说明 Skill 如何把一次性提示转化为可复用的任务规范。
- 能为一个学习任务设计触发条件、输入、流程、输出和质量检查。
- 能判断 Skill、Prompt、工具和 Agent 在系统中的职责边界。

## 核心问题

1. 什么信息需要固化在 Skill 中，才能让任务结果稳定？
2. 项目级 Skill 为什么应该纳入版本管理？
3. 如何检查一个 Skill 生成的资料没有伪造来源或泄露敏感信息？

## 一句话定义

Skill 是一组可复用、可触发的任务指导，规定智能体在特定场景下应如何理解输入、执行步骤并组织输出。

## 它解决什么问题

Skill 把一次性的提示词和经验固化为项目资产，使相似任务有稳定的流程、格式和质量检查，也便于团队共享和迭代。

## 核心机制

一个 Skill 通常包含：

1. **用途和触发条件**：什么时候应该使用它。
2. **输入约定**：需要哪些参数、资料和上下文。
3. **工作流程**：按什么顺序分析、行动和验证。
4. **输出格式**：结果应如何组织，方便阅读和复用。
5. **质量检查**：怎样判断结果完整、准确、可交付。

本项目的 Skill 放在 `.workbuddy/skills/` 下，因此属于项目级 Skill，能随仓库版本管理，并让同一项目中的协作者使用一致的生成规则。

## 应用案例

“概念学习资料生成 Skill”接收一个概念名称，先定义边界，再解释机制、举例、比较相邻概念，最后生成自测题和答案。

- 输入：`Agent`，学习者为入门者。
- 过程：按 Skill 的步骤组织内容并检查是否包含定义、示例和自测。
- 结果：产出结构稳定的 `agent.md` 学习资料。
- 适用条件：概念有明确学习目标，资料可以由学习者或教师复核，且来源能够公开核查。

## 与相邻概念的区别

| 概念 | 关注点 |
|---|---|
| Prompt | 一次交互的指令或问题 |
| Skill | 面向某类任务的可复用指令、流程和标准 |
| 工具 | 执行读取、写入、搜索或计算的能力 |

Skill 可以指导 Agent 何时、如何使用工具，但 Skill 自己通常不等于工具。

## 常见误区与边界

- Skill 不是越长越好；规则应可执行、可检查，避免互相冲突。
- Skill 不能替代事实核验和测试。
- 项目级 Skill 的约束范围通常限于使用该项目的工作场景，不应被误认为全局规则。

## 记忆要点

**Skill = 可复用的任务方法 + 输入约定 + 输出标准 + 质量检查。**

## 自测题

1. Skill 与一次性 Prompt 的主要差别是什么？
2. 项目级 Skill 为什么适合放进 Git 仓库？
3. 一个合格 Skill 至少应说明哪些内容？

## 参考答案

1. Skill 面向一类任务并包含流程、格式和检查，可复用；Prompt 常是一轮交互指令。
2. 因为它可版本管理、审阅和共享，团队能使用同一套规则。
3. 用途/触发条件、输入、工作流程、输出格式和质量检查。
