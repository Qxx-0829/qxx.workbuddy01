# Agent

## 学习目标

- 能解释 Agent 与单次大模型问答的区别。
- 能按“目标、观察、规划、行动、反馈”描述一个 Agent 的基本循环。
- 能为一个低风险任务设计最小的工具调用和验证步骤。

## 核心问题

1. Agent 为什么需要工具和反馈，而不只是生成文字？
2. 怎样判断一个任务适合交给 Agent？
3. 怎样通过权限、确认点和测试降低 Agent 行动的风险？

## 一句话定义

Agent（智能体）是能够感知目标和环境、进行规划或决策，并调用工具执行多步任务的程序或系统。

## 它解决什么问题

普通问答通常是“一次输入、一次输出”；Agent 更适合把复杂目标拆成多个步骤，并根据中间结果继续行动，例如检索资料、修改文件、运行测试和汇报结果。

## 核心机制

1. **目标与约束**：明确要完成的任务、可用资源和不能做的事情。
2. **观察**：读取用户输入、文件、工具结果或外部环境状态。
3. **规划**：把目标拆成可执行步骤，选择合适的工具。
4. **行动**：调用搜索、终端、编辑器或其他服务。
5. **反馈与迭代**：检查行动结果，必要时修正计划，直到完成或报告阻塞。

大模型通常负责理解、规划和生成调用参数；工具负责真实地读取、写入、计算或执行。Agent 不等于单独的大模型，而是模型、工具、状态和控制循环的组合。

## 应用案例

目标：把一份课程要求整理成 GitHub 项目。

- 输入：课程要求和本地空目录。
- 过程：Agent 检查环境，创建 Skill 和学习资料，运行检查，初始化 Git，提交变更，并在具备认证时创建远程仓库后 push。
- 结果：本地仓库有可审阅的文件和提交记录；远程仓库与本地提交同步。
- 适用条件：任务步骤可以被检查，工具权限可控，且失败时不会造成不可逆损失。

## 与相邻概念的区别

| 概念 | 重点 | 是否强调行动 |
|---|---|---|
| 大模型 | 理解和生成内容的模型能力 | 不一定 |
| 工作流 | 人预先规定的固定步骤 | 通常是固定的 |
| Agent | 根据目标和反馈动态选择步骤并执行 | 是 |

## 常见误区与边界

- Agent 不是“完全自主且不会出错”的人；它依赖工具权限、上下文质量和验证步骤。
- 工具调用成功不代表任务正确，仍需测试、检查 diff 或人工复核。
- 对高风险操作应设置确认点、最小权限和可回滚方案。

## 记忆要点

**Agent = 目标 + 观察 + 规划 + 工具行动 + 反馈循环。**

## 自测题

1. Agent 与只生成一段回答的大模型有什么关键区别？
2. 为什么工具结果需要再次检查？
3. 请为“整理并测试一个项目”写出 Agent 可能执行的三个步骤。

## 参考答案

1. Agent 具有面向目标的多步规划和行动能力；单次问答不一定行动。
2. 因为工具可能失败、返回异常结果，或行动本身不符合目标。
3. 例如读取项目结构、修改代码或文档、运行测试并根据结果修正。
