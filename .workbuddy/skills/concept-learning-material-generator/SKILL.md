# 概念学习资料生成 Skill

## 用途

根据用户指定的技术概念，生成适合初学者学习、复习和检查的结构化资料。

## 触发方式

当用户说“学习概念”“生成概念资料”或明确要求解释某个技术概念时使用本 Skill。

## 输入

- `concept`：要学习的概念名称。
- `audience`：学习者水平；未提供时默认为入门者。
- `context`：课程、项目或使用场景；未提供时结合概念本身推断。
- `depth`：学习深度；未提供时默认为“入门到能应用”。

## 工作流程

1. 先写 2-4 条可检验的学习目标，使用“能够解释/区分/应用”等动词。
2. 提出 2-4 个核心问题，确保后文逐一回答。
3. 明确概念边界：给出一句话定义，并说明它解决什么问题。
4. 解释核心机制：按“组成部分 -> 工作过程 -> 结果”展开，避免只给术语堆砌。
5. 提供一个贴近学习场景的应用案例，说明输入、过程、结果和适用条件。
6. 对比一个容易混淆的相邻概念，指出区别、联系和选择依据。
7. 总结常见误区、适用边界和实践建议。
8. 生成 3-5 道自测题，并在文末给出参考答案或答题要点。
9. 列出可核查的参考来源；优先使用官方文档、标准或原始论文，不确定的链接不得编造。
10. 用“目标 -> 问题 -> 结论 -> 机制 -> 应用 -> 辨析 -> 自测 -> 来源”的顺序组织内容，语言准确、简洁。

## 输出格式

```markdown
# <概念名称>

## 学习目标
## 核心问题
## 一句话定义
## 它解决什么问题
## 核心机制
## 应用案例
## 与相邻概念的区别
## 常见误区与边界
## 记忆要点
## 自测题
## 参考答案
## 参考来源
```

## 质量检查

- 定义不能循环使用概念本身作为唯一解释。
- 学习目标必须可通过资料内容和自测题检查。
- 核心问题必须在正文中得到明确回答。
- 应用案例必须说明输入、过程、结果和适用条件。
- 区分事实、类比和个人建议，不能把类比当成严格定义。
- 参考来源必须真实、可访问，并与对应论断相关；不能伪造来源。
- 对可能随版本变化的内容标注“以当前工具版本为准”。
- 生成完成后检查标题层级、术语一致性、示例完整性和自测答案覆盖度。
- 生成前后都不得读取、输出或提交 API Key、密码、个人隐私和其他敏感文件。
